## 1. 문제 정의

### 1-1. 기온은 답을 주지 않는다

세 사용자군 모두 "오늘 33도"라는 정보로는 의사결정을 못 해요. 각자 다른 숫자를 봐야 하거든요.

- **러너** — 습도가 붙은 체감온도. 30℃·습도 40%와 30℃·습도 80%는 완전히 다른 러닝이에요.
- **야외 노동자** — 법으로 정해진 임계값. 2024년 10월 산업안전보건법이 개정돼 폭염·한파로 인한 건강장해가 사업주 보건조치 의무에 추가됐고, 체감온도 31℃ 이상 장소에서의 장시간 작업이 '폭염작업'으로 규정됐어요. 33℃ 이상이면 2시간마다 20분 이상 휴식이 기준이에요. 기온이 아니라 **체감온도**가 기준선이라는 점이 핵심이에요.
- **반려견 보호자** — 지면 온도. 기온 30℃대에도 아스팔트 표면은 50~60℃까지 올라가요. 실측 사례를 보면 서울에서 기온 34.3℃일 때 아스팔트 45.5℃(+11.2℃), 미국 사례는 기온 35℃일 때 57℃(+22℃)로 조건에 따라 편차가 커요. 그래서 "손등 7초 테스트"라는 아날로그 규칙이 아직도 쓰여요.

### 1-2. 기존 날씨앱이 못 하는 것

기존 날씨앱은 **관측값을 나열**해요. 이 앱은 **판정을 내려요**. 그리고 판정 기준이 사용자마다 다르다는 걸 인정해요.

| | 기존 날씨앱 | 오늘 나가도 되나 |
| --- | --- | --- |
| 출력 | 33℃ / UV 8 / 습도 70% | "지금은 잠깐만요. 저녁 7시부터 좋아요" |
| 노면온도 | 없음 | 표면 재질별 추정 (아스팔트/보도블록/잔디/흙) |
| 기준 | 모두에게 동일 | 프로필별 가중치·임계값 |
| 시간 축 | 시간별 기온 나열 | **나가도 되는 시간창**을 색으로 |

### 1-3. 왜 지금, 왜 토스인가

- 폭염 예방조치가 2025년부터 권고에서 법적 의무로 바뀌면서 야외 노동 현장에서 체감온도를 확인할 실질적 수요가 생겼어요.
- 이 앱은 **하루 1~3회, 30초 이내**로 쓰는 서비스예요. 앱을 새로 설치할 만큼의 동기는 안 생기지만, 이미 깔린 토스 안에 있으면 씁니다. 미니앱 포맷과 사용 패턴이 정확히 맞아요.
- 위치·저장소·광고까지 SDK로 다 해결되고, 회원가입이 없어요.

## 2. 타깃과 사용 시나리오

### 프로필 A. 러너

- 상황: 퇴근 후 한강. 나갈지 말지, 나간다면 몇 시에 나갈지.
- 판단 축: 체감온도 > 자외선 > 노면
- 원하는 출력: "오늘은 7시 이후가 좋아요. 5~6시는 피해요"
- 진입 시각: 오전 7시대, 오후 5~8시대

### 프로필 B. 야외 노동자 (+ 현장 관리자)

- 상황: 건설·조경·배달·설비. 오늘 작업 강도와 휴식 배치를 정해야 함.
- 판단 축: 체감온도(법정 31/33℃ 기준에 직접 정렬) > 자외선 > 노면
- 원하는 출력: "지금 체감 34℃. 2시간마다 20분 휴식 구간이에요"
- 진입 시각: 오전 6~8시(작업 계획), 정오 전후(재확인)
- 주의: **법률 자문이나 안전 진단이 아니라 기상정보 안내**라는 포지션을 화면에서 명확히 해야 해요.

### 프로필 C. 반려견 보호자

- 상황: 배변 산책은 미룰 수 없음. 지금 나갈지, 코스를 바꿀지.
- 판단 축: **노면온도 > 지면 높이 체감온도 > 자외선**
- 원하는 출력: "아스팔트 51℃. 지금은 흙길이나 잔디로 가요. 8시 이후 괜찮아요"
- 진입 시각: 오전 6~9시, 오후 7~10시
- 이 프로필이 **재방문 빈도가 가장 높고**(하루 2회 이상 고정), 앱의 차별점(노면온도)과 가장 강하게 결합돼요. → **런칭 시 대표 프로필로 밀 것**

### 프로필 전환은 정책상 필수 설계

앱인토스는 동일 워크스페이스에서 핵심 기능이 같은 미니앱을 여러 개 출시하는 것을 제한해요. 핵심 기능이 같으면 테마·대상·주제만 다르게 구성해도 별도 미니앱으로 인정되지 않고, 검수 단계에서 구조 유사도가 높다고 판단되면 반려될 수 있어요. **'러너용 앱'과 '반려견용 앱'을 따로 내는 전략은 불가능해요.** 하나의 앱, 홈 상단 프로필 스위처로 가야 해요.

## 3. 판정 엔진 설계

### 3-1. 구조

```
입력 3종 ──▶ 각각 0~100 서브스코어로 정규화
                    │
                    ├─▶ 프로필별 가중합 ─┐
                    │                    ├─▶ 위험도 0~100 ─▶ 5단계 판정 ─▶ 한 줄 문장
                    └─▶ 하드 게이트 ─────┘
```

가중합만 쓰면 "자외선은 낮은데 노면이 60℃"인 상황이 평균에 묻혀요. 그래서 **하드 게이트**를 얹어 특정 지표가 임계를 넘으면 최소 등급을 강제해요.

### 3-2. 5단계 판정

| 등급 | 위험도 | 컬러 | 러너 문장 예시 | 반려견 문장 예시 |
| --- | --- | --- | --- | --- |
| 좋음 | 0–19 | `#0E9F6E` | 지금 나가기 좋아요 | 지금 산책하기 좋아요 |
| 보통 | 20–39 | `#A3C13A` | 물만 챙기면 괜찮아요 | 그늘 위주로 걸어요 |
| 주의 | 40–59 | `#F5A524` | 강도를 낮추고 짧게 뛰어요 | 아스팔트는 피하고 짧게 다녀와요 |
| 위험 | 60–79 | `#F2711C` | 지금은 실내가 좋아요 | 지금은 흙길이나 잔디로만 가요 |
| 매우 위험 | 80–100 | `#E03131` | 저녁까지 미뤄요 | 배변만 짧게, 안고 이동해요 |

색 램프를 초록→연두→주황→진주황→빨강의 **열(熱) 그라데이션**으로 잡은 건, 이 앱의 주제 자체가 온도라서예요. 별도 아이콘 없이 색만으로 온도감이 전달돼요.

### 3-3. 서브스코어 정규화

**체감온도 `S_heat`** — 구간 경계를 법정 기준(31℃/33℃)에 맞춰 고정했어요.

| 체감온도 | 서브스코어 |
| --- | --- |
| ≤ 25℃ | 0 |
| 25 → 31℃ | 0 → 40 (선형) |
| 31 → 33℃ | 40 → 60 |
| 33 → 35℃ | 60 → 80 |
| 35 → 38℃ | 80 → 100 |
| ≥ 38℃ | 100 |

**자외선 `S_uv`** — 기상청 자외선지수 단계 기준(낮음 3 미만 / 보통 3~5 / 높음 6~7 / 매우높음 8~10 / 위험 11 이상)에 정렬했어요.

| UVI | 서브스코어 |
| --- | --- |
| 0–2 (낮음) | 0–15 |
| 3–5 (보통) | 20–40 |
| 6–7 (높음) | 45–60 |
| 8–10 (매우높음) | 65–85 |
| 11+ (위험) | 100 |

**노면온도 `S_road`** — 50℃ 전후를 화상 위험 변곡점으로 잡았어요. 여름 한낮 아스팔트가 50~60℃에 도달하고 그 구간에서 짧은 접촉으로도 발바닥 화상이 생긴다는 게 공통된 안내예요.

| 노면온도 | 서브스코어 |
| --- | --- |
| ≤ 35℃ | 0 |
| 35 → 45℃ | 0 → 40 |
| 45 → 52℃ | 40 → 70 |
| 52 → 60℃ | 70 → 90 |
| ≥ 60℃ | 100 |

### 3-4. 프로필별 가중치

| 프로필 | 체감온도 | 자외선 | 노면 |
| --- | --- | --- | --- |
| 러너 | 0.55 | 0.30 | 0.15 |
| 야외 노동자 | 0.65 | 0.25 | 0.10 |
| 반려견 | 0.40 | 0.10 | **0.50** |

반려견 프로필은 체감온도를 그대로 쓰지 않고 **지면 높이로 보정**해요. 몸높이가 낮아 노면 복사열을 직접 받으니까요.

```
T_felt_dog = T_air + 0.35 × (T_road − T_air)
```

기온 32℃ / 노면 52℃면 반려견 체감은 39℃로 계산돼요. 사람 기준 "덥지만 견딜 만"이 개 기준으로는 "위험"이 되는 지점이 이 보정에서 나와요.

### 3-5. 하드 게이트

| 조건 | 강제 최소 등급 |
| --- | --- |
| 체감온도 ≥ 35℃ | 위험 (전 프로필) |
| 체감온도 ≥ 33℃ + 야외 노동자 | 주의 + 휴식 배너 노출 |
| 노면 ≥ 52℃ + 반려견 | 위험 |
| 노면 ≥ 60℃ | 매우 위험 (전 프로필) |
| UVI ≥ 11 | 주의 |
| 낙뢰 예보 / 시간당 강수 15mm↑ | 매우 위험 (사유 대체 표시) |

### 3-6. 노면온도 추정 모델 (이 앱의 심장)

노면온도는 대부분의 지점에서 실시간 관측값을 얻을 수 없어요. 그래서 **추정 모델 + 관측 보정** 구조로 가요.

```
T_road = T_air + ΔT

ΔT = k_surface × SR_norm × (1 − 0.03 × WS) + R_residual

  k_surface  : 아스팔트 24 / 콘크리트·보도블록 18 / 우레탄 15 / 잔디 7 / 흙 6
  SR_norm    : 일사량 정규화값 (실측 일사량 ÷ 1000 W/m²)
               예보 구간에서는 태양고도 × 운량계수(SKY)로 추정
  WS         : 풍속 (m/s), 최대 40% 감쇠로 클램프
  R_residual : 잔열항. 일몰 후 τ=90분 지수감쇠, 초기값 +5℃
```

**모델 캘리브레이션 검증**

| 사례 | 조건 | 모델 ΔT | 실측 ΔT |
| --- | --- | --- | --- |
| 미국, 청천 정오 | k=24, SR=0.90, WS=1 | +21.0℃ | +22℃ (35→57) |
| 서울, 부분 운량 오후 | k=24, SR=0.50, WS=2 | +11.3℃ | +11.2℃ (34.3→45.5) |

두 사례 모두 오차 1℃ 이내로 들어와요. 다만 이건 2점 캘리브레이션이라, 운영에 들어가면 ASOS 지면온도 관측값으로 계속 보정해야 해요.

**보정 루프** — 기상청 종관기상관측(ASOS)은 기온·습도·풍속과 함께 **일사량, 지면온도, 초상온도**를 관측 요소로 제공해요. 백엔드에서 매시간 ASOS 지면온도 실측과 모델 출력의 잔차를 지점별로 누적하고, 지역·시간대별 보정 계수를 갱신해요. ASOS 지면온도는 나지(맨땅) 기준이라 아스팔트와 직접 같지는 않지만, **일사·풍속에 따른 ΔT 반응 곡선을 맞추는 기준선**으로는 충분히 쓸 수 있어요.

**정직성 원칙** — 노면온도는 추정치예요. 화면에 반드시 다음을 표기해요.

- 숫자 옆에 `추정` 배지
- 근거 한 줄: "기온 32℃ + 강한 햇빛 + 약한 바람 기준"
- 검증 유도: "손등을 7초 대보고 뜨거우면 피해요" — 앱을 맹신하지 않게 하는 안전장치이자, 보호자들이 이미 아는 규칙이라 신뢰를 얻는 장치예요.

### 3-7. 시간창 계산

06:00~24:00을 1시간 간격으로 위험도를 계산한 뒤, 두 가지를 뽑아요.

1. **지금 판정** — 현재 시각 슬롯
2. **최적 창** — '보통' 이하가 90분 이상 연속되는 구간 중, 현재 시각 이후 가장 이른 것

```
if (지금이 '주의' 이상) → "지금은 {대안}. {최적창 시작}부터 좋아요"
else if (2시간 내 악화)  → "지금 괜찮아요. {악화 시각}부터는 피해요"
else                    → "{최적창}까지 좋아요"
```

### 3-8. 문장은 규칙 기반으로 생성 (LLM 미사용)

생성형 AI로 결과를 만들면 앱인토스 정책상 **최초 이용 시점 사전 고지 + 결과물에 AI 라벨 표시**가 의무이고, 위반 시 최대 3,000만 원 과태료 대상이에요. 판정 문장은 어차피 유한한 조합이라 LLM을 쓸 이유가 없어요. **템플릿 × 프로필 × 등급 × 시간대 조합으로 규칙 기반 생성**하면 고지 의무를 피하면서 응답 속도와 일관성까지 얻어요.

| 폭염특보 | 기상청 특보 | 수시 | 상단 경보 배너 |

### 반드시 알아야 할 변경사항

기상청은 **2026년 5월 1일부로 체감온도(대상·환경별) 서비스를 종료**했어요. 기존에 생활기상지수에서 받던 '실외작업장 체감온도' 같은 세분화 값을 더는 API로 받을 수 없어요.

→ **체감온도는 직접 계산해야 해요.** 이게 진입장벽이자 차별점이에요.

```
여름철 (5~9월): 습구온도 기반 체감온도 식
  Tw = Stull(2011) 근사식으로 기온·상대습도에서 습구온도 산출
  체감온도 = f(Ta, Tw)  ← 기상청 여름철 체감온도 산식

겨울철 (11~3월): 풍속냉각지수(Wind Chill) 식
  체감온도 = 13.12 + 0.6215×Ta − 11.37×V^0.16 + 0.3965×Ta×V^0.16
```

### 아키텍처: 백엔드 캐시 레이어 필수

클라이언트에서 기상청 API를 직접 부르면 안 돼요. 이유가 셋이에요.

1. API 키가 번들에 노출돼요
2. CORS가 막혀요
3. 사용자 수 × 호출 수로 트래픽 한도를 금방 소진해요

```
미니앱(CSR)  →  캐시 API (Cloudflare Workers / Supabase Edge)  →  기상청 API
                       ↓
              KV 캐시: key = `${nx}:${ny}:${발표시각}`
              TTL: 실황 10분 / 예보 3시간 / UV 6시간
```

격자 단위로 캐싱하면 같은 동네 사용자 1,000명이 호출 1회를 공유해요. 앱인토스는 서버 사이드 렌더링(SSR)을 사용할 수 없고 CSR 또는 SSG만 허용하니, 백엔드는 데이터 API 전용으로만 두면 돼요.

## 5. 화면 설계

### 5-1. 정보 구조

```
홈 (단일 스크롤)
├─ [고정] 프로필 스위처 · 지역
├─ 판정 카드          ← 진입 후 첫 화면에서 결론이 끝남
├─ 지표 3종 카드      ← 체감 / 자외선 / 노면
├─ 시간창 스트립      ← 18칸 컬러 바
├─ 실천 팁 2~3개
└─ [배너 광고]
    │
    ├─ 시간창 상세 (탭)
    ├─ 지표 상세 (근거 공개)
    └─ 설정 (프로필·지역·알림)
```

탭바는 쓰지 않아요. 앱인토스에서 탭바는 필수가 아니고, 쓸 경우 토스가 제공하는 플로팅 형태를 그대로 따라야 하는데(2~5개), 이 앱은 홈 단일 화면으로 결론이 끝나서 탭을 둘 이유가 없어요. 화면 수를 줄이는 게 30초 사용 패턴에 맞아요.

### 5-2. 화면별 정의

**[F1] 진입 / 프로필 선택**

- 최초 1회만. 이후엔 Storage에서 읽어 바로 홈으로.
- 3개 카드: 러너 / 야외 작업 / 반려견 산책
- 하단: 위치 권한 요청 사유 설명 → CTA "내 위치로 시작하기" / 보조 "지역 직접 고르기"
- **정책 주의:** 진입하자마자 바텀시트를 띄우면 안 돼요. 광고성은 물론 알림 동의 바텀시트도 포함이에요. 프로필 선택은 반드시 **인라인 전체 화면**으로 구현해요.

**[F2] 홈 — 판정**

첫 화면 스크롤 없이 보이는 영역에 다음이 다 들어가야 해요.

```
┌──────────────────────────────┐
│ 🐕 반려견 산책  ▾    고양시 일산동구 ▾ │
│                              │
│         지금은                │
│    잠깐만 다녀와요             │  ← 24pt Bold, 판정 컬러
│                              │
│  아스팔트가 51℃까지 올라        │  ← 15pt, grey700
│  발바닥에 무리가 갈 수 있어요     │
│                              │
│  ┌────────────────────────┐  │
│  │ 저녁 7시 30분부터 좋아요  │  │  ← 최적창 하이라이트
│  └────────────────────────┘  │
└──────────────────────────────┘
```

**[F3] 지표 3종 카드**

가로 스크롤 아님. 세로 3단 ListRow 형태.

| | 표시 | 보조 |
| --- | --- | --- |
| 체감온도 | 36℃ | 기온 32℃ · 습도 68% |
| 자외선 | 8 매우높음 | 자외선지수 |
| 노면온도 | 51℃ `추정` | 아스팔트 기준 · 흙길 38℃ |

반려견 프로필일 땐 노면 카드가 맨 위로 올라가고 크기가 커져요. 프로필에 따라 **정보 위계 자체가 바뀌는 것**이 이 앱의 설계 핵심이에요.

**[F4] 시간창 스트립**

- 06시~24시, 18칸. 각 칸이 등급 컬러.
- 현재 시각에 흰 테두리 인디케이터.
- '보통' 이하 연속 구간에 밑줄 + "산책하기 좋은 시간" 라벨.
- 탭하면 해당 시각의 3지표 툴팁.

**[F5] 지표 상세 — 왜 이 판정인가**

신뢰의 핵심 화면이에요. 판정 근거를 전부 공개해요.

- 노면온도 계산 근거: 기온 32℃ + 일사 강함 + 풍속 1.2m/s → +19℃
- 표면별 비교 바: 아스팔트 51 / 보도블록 46 / 잔디 39 / 흙 38
- 손등 7초 테스트 안내
- 데이터 출처: 기상청 (필수 표기)
- 고지: "기상정보를 바탕으로 한 참고용 안내예요. 의학적 판단이나 안전 진단을 대신하지 않아요."

**[F6] 설정**

- 프로필 변경 / 지역 관리(최대 3개) / 알림 시간대
- 알림 동의는 **설정 화면 안에서만** 요청해요. 뒤로가기 시점에 붙이면 안 돼요. 앱인토스는 뒤로가기 눌렀을 때 알림 동의를 유도하는 바텀시트를 다크패턴으로 명시하고 있어요.

**[F7] 위치 권한 거부 fallback**

권한을 허용하지 않아도 나머지 기능은 계속 정상 작동해야 해요. 지역 직접 선택으로 100% 동일한 기능을 제공하고, 재요청은 화면 하단에 조용한 텍스트 링크로만 둬요.

## 6. 디자인 프레임

별도 HTML 파일로 6개 프레임을 제작했어요. 아래는 그 근거가 된 규격이에요.

### 6-1. 기준 해상도

앱인토스 권장 기준에 따라 **세로형 논리 해상도 375 × 812**를 기준으로 설계해요. 권장 범위는 360×640 ~ 420×740이고, 실제 미니앱 트래픽의 약 70~80%가 좁은 쪽 360~420 범위에 몰려 있어요. 기기별 대응이 아니라 **기준 해상도 하나 + 스케일링**으로 가고, 에셋은 1x·2x만 준비해요.

### 6-2. 컬러 토큰

```
/* 브랜드 */
--brand-primary : #0E9F6E   ← granite.config.ts의 brand.primaryColor
--brand-sub     : #0B7A54

/* 판정 램프 (열 그라데이션) */
--lv1-good      : #0E9F6E
--lv2-fair      : #A3C13A
--lv3-caution   : #F5A524
--lv4-danger    : #F2711C
--lv5-severe    : #E03131

/* 뉴트럴 — TDS 계열 근사값 */
--grey900 : #191F28   본문 제목
--grey700 : #4E5968   본문
--grey500 : #8B95A1   보조·캡션
--grey200 : #E5E8EB   구분선
--grey100 : #F2F4F6   카드 배경
--white   : #FFFFFF
```

**브랜드 컬러를 토스 블루(#3182F6) 계열로 잡지 않은 이유:** 앱인토스 브랜딩 가이드는 사용자가 토스와 파트너 서비스를 혼동하지 않는 것을 중요 기준으로 두고 있어요. 이 앱은 그늘·안전을 뜻하는 딥 그린을 브랜드 컬러로 써서 판정 램프의 '좋음'과도 자연스럽게 이어지게 했어요. 브랜드 컬러는 토스 내 진입점·브릿지·버튼에 쓰이고, 색 대비 기준에 미달하면 자동 보정되니 #0E9F6E 정도의 명도가 안전해요.

### 6-3. 타이포

| 역할 | 크기/굵기 | 용도 |
| --- | --- | --- |
| Display | 32 / Bold | 판정 한 줄 |
| Title | 20 / Bold | 섹션 헤더 |
| Body | 15 / Regular | 설명문 |
| Caption | 13 / Medium | 근거·출처 |
| Number | 28 / Bold, tabular | 지표 수치 |

지표 숫자에 tabular-nums를 적용해서 값이 바뀔 때 자릿수가 흔들리지 않게 해요.

### 6-4. 그래픽 원칙

앱인토스 그래픽 가이드가 요구하는 것들이에요.

- 아이콘은 화면에서 24~40px로 사용해요.
- 아이콘·이모지를 두 개 이상 병렬 조합하지 않아요. 한 번에 하나만.
- 한 화면에 큰 그래픽은 하나만. 나머지는 아이콘으로 대체해요.
- 장식적 이펙트, 파티클, 과한 그라데이션은 쓰지 않아요.
- 부정적이거나 호소하는 감정 표현은 다크패턴에 해당해요. **위험 등급이어도 겁주는 일러스트를 쓰지 않아요.** 색과 문장으로만 전달해요.
- 토스가 제공하는 그래픽 리소스는 화면 내 UI 용도로만 쓸 수 있고, 앱 로고나 썸네일에는 쓸 수 없어요. **로고는 직접 제작해야 해요** (600×600px 각진 정사각형, 둥근 모서리 불가, 배경 필수).

### 6-5. UX 라이팅 규칙

앱인토스 UX 라이팅 가이드를 그대로 적용해요.

| 원칙 | 나쁜 예 | 좋은 예 |
| --- | --- | --- |
| 해요체 | 외출을 삼가십시오 | 지금은 실내가 좋아요 |
| 능동형 | 산책이 권장되지 않습니다 | 지금은 잠깐만 다녀와요 |
| 긍정형 | 지금은 나갈 수 없어요 | 저녁 7시부터 나가기 좋아요 |
| 캐주얼 경어 | 확인하시겠어요? | 자세히 볼래요 |
| 명사+명사 금지 | 노면온도 상승 주의 | 아스팔트가 뜨거워요 |
| 다이얼로그 왼쪽 버튼 | 취소 | **닫기** |
| 되어요 → 돼요 | 위험해지게 되어요 | 위험해져요 |

부정형을 써도 되는 예외가 있어요. **기능을 쓸 수 없는 상황을 명확히 알려야 할 때**예요. 위치 권한이 없을 때 "지금 위치를 확인할 수 없어요. 지역을 직접 고르면 똑같이 볼 수 있어요"처럼 이유와 대안을 함께 줘요.

## 8. 수익화

### 8-1. 광고 배치

앱인토스 광고 수익 공식은 `예상 수익 = 노출 수 × eCPM ÷ 1,000`이고, 세 유형을 조합할 때 가장 효과가 커요.

| 유형 | 배치 | 근거 |
| --- | --- | --- |
| **배너** | 홈 최하단 (스크롤 영역 안) | 노출 수가 가장 많음. 이 앱은 하루 2~3회 재방문이라 배너가 기본 수익축 |
| **리워드** | "이번 주 산책 좋은 시간 보기" 해금 | 사용자가 직접 선택하고 집중해서 봐서 eCPM이 가장 높음. 보상이 명확한 순간에 연결 |
| **전면형** | ❌ 사용 안 함 | 세션이 30초로 짧아서 흐름을 끊음. 정책상 인트로·로딩 노출도 금지 |

전면형을 빼는 건 수익을 일부 포기하는 선택이지만, 진입 3초 안에 결론을 주는 게 이 앱의 유일한 가치라서 그걸 깨면 재방문이 무너져요.

### 8-2. 정산 구조

광고 수익은 광고 송출 비용과 앱인토스 수수료를 차감한 뒤 정산돼요.

```
광고 매출 ₩10,000
  −  미디에이션/송출 운영비 약 30%
  =  광고 수익 ₩7,000
  −  앱인토스 수수료 15% (광고 대행 비용)
  =  파트너사 정산금
```

**주의: 토스 수수료 0% 프로모션은 2026년 3월 31일자로 종료됐어요.** 현재(2026년 7월) 기준으로는 15%가 적용된다고 보고 수익을 계산해야 해요.

- 정산 내역 확정: 익월 2영업일 오후 12시
- 정산금 지급: 익월 말 영업일
- 광고 수익 부가세는 **역발행 세금계산서** 방식이라, 사업자 공동인증서 + 팝빌 가입이 사전에 필요해요. 매월 4영업일까지 승인하지 않으면 지급이 이월되고, 2회 이상 미승인 시 미니앱 운영이 중단될 수 있어요. **이건 개발보다 먼저 세팅해둘 것.**

### 8-3. 성장 루프

- **공유 리워드** — "우리 동네 지금 산책 지수" 카드 공유. `getTossShareLink`로 토스 앱에서 바로 열리는 링크 생성.
- **스마트 발송** — 아침 6시 30분 "오늘 산책하기 좋은 시간은 7시~9시예요". 이 앱은 알림이 곧 핵심 가치라 푸시 동의율이 높게 나올 구조예요. 단, 동의 요청 타이밍은 설정 화면 안에서만.
- **유입경로 레퍼러 / Analytics** — 프로필별 리텐션 차이를 측정해서 대표 프로필 노출 순서를 조정해요.

## 9. 개발 계획

### 9-1. 스택

```bash
npx create-ait-app today-outside
# 패키지 매니저: npm
# 템플릿: react-ts (React + TypeScript)
# TDS 사용: Y
```

```ts
// granite.config.ts
import { defineConfig } from "@apps-in-toss/web-framework/config";

export default defineConfig({
  appName: "today-outside",
  brand: {
    displayName: "오늘 나가도 되나",
    primaryColor: "#0E9F6E",
    icon: "<콘솔 업로드 로고 URL>",
  },
  web: {
    host: "localhost",
    port: 5173,
    commands: { dev: "vite dev", build: "vite build" },
  },
  permissions: ["location"],
  outdir: "dist",

```

**사용하는 SDK**

| 기능 | 함수 |
| --- | --- |
| 현재 위치 | `getCurrentLocation({ accuracy: Accuracy.Balanced })` — 오차 수백 미터면 격자 특정에 충분하고 배터리도 아껴요 |
| 권한 상태 | `getCurrentLocation.getPermission()` → `allowed`/`denied`/`notDetermined`/`osPermissionDenied` 분기 |
| 권한 재요청 | `getCurrentLocation.openPermissionDialog()` — 설정 화면에서만 호출 |
| 데이터 저장 | `Storage` — 프로필, 지역 목록, 알림 설정 |
| 광고 | `showAppsInTossAdMob` (리워드), `BannerAd` (WebView 배너) |
| 공유 | `getTossShareLink`, `share` |
| 알림 | 스마트 발송 |
| 분석 | `Analytics`, `referrer` |
| Safe Area | 노치·둥근 모서리 대응 |

`startUpdateLocation`은 쓰지 않아요. 실시간 추적이 필요 없고 배터리만 먹어요.

### 9-3. 일정

| 주차 | 작업 |
| --- | --- |
| **W1** | 판정 엔진 순수 함수 구현 + 단위 테스트 / 캐시 API 배포 / 기상청 키 발급 |

테스트 기기는 화면 비율이 다른 2~3종 + Safe Area가 큰 1종 + 작은 화면 1종이면 충분해요.

### 9-4. 릴리스 후 개선

- **노면 모델 실측 피드백** — 지표 상세 화면에 "실제로 어땠나요?" 3점 척도(생각보다 시원 / 비슷 / 더 뜨거움). 지역·시간대별 보정 계수 학습에 씀.
- **표면 재질 선택** — 사용자가 자주 다니는 코스 재질(아스팔트/보도블록/공원 흙길)을 저장해서 기본 노면 계산에 반영.
- **작업 휴식 타이머** — 야외 노동자 프로필 한정. 체감 33℃ 이상이면 2시간 주기 휴식 알림. 법정 기준선을 그대로 쓰되, 안전 조치가 아니라 참고 알림이라는 걸 명시.
